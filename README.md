## 0.7.0：全ページホバー・分類・バックアップ・詳細パネル

- TIFF・PPTの複数ページは、マウスを約0.4秒止めると全ページをタイル表示します。画面の約85%以内に収まる配置を選び、各ページは最大512pxです。多数ページでは縮小し、極端に小さい場合はページ番号を省略します。単一ページのホバーは従来通りです。全ページを別窓で開くメニューは廃止しました。
- ホバーは保存済みページ画像だけをバックグラウンドで読み込みます。元ファイルの取得・statは行いません。未生成ページは再生成完了後に利用できます。
- 右側にメタ情報・メモ・タグ・お気に入りの詳細パネルを追加しました。上部の詳細情報ボタンと右クリックの詳細表示メニューは廃止しました。パネル幅は境界のドラッグで変更できます。
- タグはカンマ区切りで入力。「メモ・タグ・お気に入りを保存」で保存します。別ファイルを選ぶ際にも自動保存します。保存失敗時は編集内容を残します。「編集を破棄して再読込」で取り消せます。終了時は未保存編集を確認します。
- 検索対象はファイル名・メモ・タグ。「★ のみ」でお気に入りに絞り込みます。お気に入りはファイル名の先頭にも★を表示します。
- 完了・全体・未完了・タイムアウト・エラー・処理中件数と、処理中ファイル名・経過秒を表示します。未完了件数には処理中やタイムアウト保留も含みます。
- 「生成を一時停止」は新しい自動生成の開始を止めます。実行中のダウンロード・生成は完了またはタイムアウトまで継続します。フォルダの定期スキャンは継続します。一時停止状態は再起動後も保持します。「生成を再開」で解除してください。
- 「DBバックアップ」で任意の新しい `.sqlite3` ファイルへ保存できます。SQLite Backup APIを使用し、稼働中でも整合性のあるDBをバックグラウンド保存します。メモ・タグ・お気に入り・設定・サムネイル・全ページ画像を含み、元ファイルは含みません。既存ファイルには上書きしないので毎回新しい名前を指定してください。
- 復元はアプリをトレイから完全終了した後に行います。現在のアプリ保存フォルダを退避し、同じ場所に保存フォルダを作り、バックアップを `catalog.sqlite3` という名前で配置して起動します。古い `-wal` / `-shm` ファイルと混在させないでください。復元専用UIはありません。
- DBは自動拡張され、既存のメモ・サムネイルを保持します。登録解除・削除確定時はタグ・お気に入りも関連データとともに除去します。

## 0.6.0：画像メタ情報・ユーザーメモ

- ファイルを選んで上部「メタ情報・メモ」、または右クリック「メタ情報・メモ・エラー詳細」で開きます。
- 画像形式、元の幅・高さ、色モード、フレーム数、DPI、EXIF（撮影日時・カメラ・露出・GPS等、ファイルに存在する項目）をDBに保存します。TIFFは先頭ページの情報です。バイナリ値はサイズのみ、各値は最大4000文字です。全メタデータの完全保存・IPTC/XMP解析には対応していません。
- メタ情報はサムネイル生成時に作業用コピーから取得します。既存画像は必要に応じて「再スキャン・再生成」してください。この操作は未キャッシュファイルを取得する場合があります。閲覧やメモ保存では元ファイルを読み書きしません。
- メモは画像・動画・PPTすべてに入力可能。「メモを保存」で確定し、未保存で閉じる場合は確認します。ファイル名・メモを検索できます。メタ情報の全文検索は未対応です。
- メモは再スキャン・再生成・アプリ再起動後も保持します。登録解除・削除候補の確定削除では関連メモもDBから削除されます。ファイルの移動・名前変更にメモを自動追跡する機能はありません。
- DBは自動拡張します。メタ情報取得のための一斉再生成は行いません。前版の512px移行が未完了の場合は従来の再生成が継続します。
- GPS等を含む場合があるため、DBを共有する場合は保存内容を確認してください。

Windows向けの画像・動画・PowerPointサムネイルカタログです。Python / PySide6 / SQLiteで実装しています。

## 0.5.0：512px・ホバープレビュー・全ページ表示

全形式の保存サムネイルを長辺最大512pxに変更しました。TIFFとPowerPoint（ppt / pptx / pptm）は一覧では先頭ページを表示します。複数ページは画像上の「N p」バッジとファイル名の「Nページ」で区別できます。ページ数は生成完了後に表示されます。

| 表示 | サイズ・操作 |
|---|---|
| メイン一覧 | 180×140の表示枠に縮小、先頭ページのみ |
| ホバー | 約0.4秒静止すると、保存済み画像を長辺最大512pxで表示 |
| 全ページ | 右クリック「全ページのサムネイルを別ウィンドウで表示」 |
| 全ページウィンドウの一覧 | 240×240の枠。ページ番号付き、ホバーにも対応 |

縦横比は維持し、小さい元画像は拡大しません。ホバーは縮小せずに表示し、位置を調整して画面内に収めます。512pxはQtの論理座標での大きさです。Windowsの拡大率により物理ピクセル数は変わります。スクロール・クリック・マウス退出でポップアップを閉じます。生成前は画像ポップアップを出しません。「ファイル情報・エラー詳細」は右クリックから確認できます。

既存の全形式のサムネイルを初回起動時に一度だけ再生成対象にします。自動生成ONで順次更新されるため、Boxの未キャッシュファイルは再取得される場合があります。旧サムネイルは生成成功まで表示し続けます。タイムアウト保留フラグは維持します。元ファイルは変更しません。旧4ページ合成画像も更新完了後に先頭ページの画像へ切り替わります。

TIFF・PowerPointはサムネイル生成時に全ページを1ページずつ処理します。各ページの512px JPEGをDBへ保存するため、ページ数に応じて生成時間・DB容量が増えます。全ページの生成成功後に一括反映し、失敗や時間切れでは旧画像を維持します。従来の30分タイムアウトが適用され、必要なら延長できます。

ホバーと全ページウィンドウはDBのみを読み、元ファイルの再取得は行いません。ページ画像を必要に応じて非同期で読み込むため、全ページ分の展開済み画像を一括でメモリに置きません。1ページのTIFF・PPTも別窓で確認でき、0スライドのPPTは生成エラーとして扱います。

TIFFは実ファイルの1～5ページ、PowerPointはCOMの代役を使って1～5スライドの書き出し回数と画像を検証しました。5ページ目も保存・表示するテスト、ホバー時の実サイズ、DB以外にアクセスしないこと、失敗時のDBロールバックも確認しています。Windowsの実PowerPointでの確認は未実施です。

## 0.3.1の修正

登録解除後、SQLiteのファイルIDが別ファイルに再利用されたときに古いサムネイルキャッシュが表示される不具合を修正しました。

- 登録ごとに128ビットのランダム識別子を発行し、ファイルID・登録識別子・更新番号の組み合わせでキャッシュを管理します。
- 削除された登録や古い更新番号の非同期読み込み結果は破棄します。DB読取時にも登録識別子と更新番号を確認します。
- 古い生成処理の保存・失敗報告も登録識別子で検査し、同じパスを再登録した場合でも別の登録を書き換えません。
- 既存DBは起動時に自動拡張します。既存のサムネイルとファイルIDは保持するため、全件再生成は不要です。

更新時はトレイから旧版を完全終了し、この版に差し替えて起動してください。

## 並列処理と元ファイルの保護

- メタデータ走査をフォルダ単位で4スレッド化。DBへの反映は1か所に集約します。単一フォルダ内の列挙自体は1スレッドです。
- スキャンと取得・生成を独立実行。取得・生成は最大3件並列、PowerPoint生成のみ同時1件です。
- 取得を含めた処理時間の上限を既定30分に変更。画面で1～1440分に設定できます。実行済みの処理は開始時の設定を使います。
- 元ファイルは読み取りだけで作業用コピーへ転送し、全デコーダーとOfficeにはコピーを渡します。
- 明示的な「元ファイルを開く」操作は例外で、既定アプリに元のパスを渡します。開いた外部アプリで編集・保存した場合は元ファイルに反映されます。

元ファイルの削除・移動・上書き・属性変更・保存を呼ぶ処理はありません。更新するのはアプリのDB、設定、生成画像と作業用ファイルです。削除候補の承認ではDBのレコードとサムネイルだけを除去します。生成に使ったアプリ所有の一時フォルダは後片付けします。Box側によるダウンロードキャッシュの作成やOSのアクセス日時管理は通常の読み取りに付随する動作です。

## セットアップ

1. このZIPをローカルの任意のフォルダに展開します。
2. **Python 3.12（64 bit）**をインストールします。WindowsのPythonランチャー `py` が必要です。
3. `setup.bat` を実行します。PySide6 / Pillow / pywin32をインストールします。
4. `start.bat` を実行します。

企業環境でpipのネット接続が制限される場合、承認済みのパッケージ配布元またはオフラインwheelを使って、同じ依存パッケージを `.venv` に導入してください。

動画には別途 **FFmpeg** が必要です。`ffmpeg -version` を実行できるようPATHを設定してください。PowerPointの生成には **Microsoft PowerPointデスクトップ版**が必要です。これらの不足は該当ファイルの生成エラーとして表示され、画像の閲覧などは継続できます。

手動で準備する場合:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py
```

## 使い方

- 「フォルダ登録」から対象を追加。複数登録でき、重複する範囲は上位の登録に統合します。
- 初回登録後、メタデータを走査しサムネイルを順次作成します。
- **自動生成は既定でON**です。未キャッシュのBoxファイルは生成時に取得されます。メタデータだけ登録したい場合、フォルダ登録前にOFFにしてください。
- 左のフォルダツリーで絞り込み。「サブフォルダを含む」で再帰表示を切り替えます。
- ファイル名検索、Ctrl/Shiftによる複数選択、Ctrl+Aで表示中の全件選択に対応します。
- ダブルクリックで元ファイルを既定アプリで開きます。未キャッシュの場合、外部アプリ側でダウンロード待ちになります。
- 「選択を再生成」で手動再生成を予約します。自動生成がOFFの間は待機します。
- 右上で定期スキャン間隔を変更できます。既定は10分です。
- 閉じるボタンではトレイに格納します。終了はトレイの「終了」を選んでください。
- 二重起動を防止します。再実行してウィンドウが出ない場合はトレイを確認してください。

## 削除候補

正常に完了したルートフォルダのスキャンで見つからなかったファイルを「削除候補」にします。サムネイルと情報は保持します。アクセス拒否・接続断・中断などでスキャンが失敗すると、そのルート全体の新たな削除判定を保留します。

「削除候補のみ」をONにして項目を選び、「選択候補をカタログから削除」を押してください。確認ダイアログの詳細に対象パスを表示します。承認後、存在を再確認してDB内の情報と画像だけを削除します。元ファイルに削除・移動・書き込み操作はしません。再出現した項目はマークを解除し、確認不能な項目は保持します。

## Box Driveとメタデータ

- スキャンは `os.scandir()` と `DirEntry.stat(follow_symlinks=False)` でパス・サイズ・最終更新日時を取得します。
- **メタデータ取得では元ファイル本体がダウンロードされない、という合意済みの前提**に基づきます。Box実機での検証は未実施です。
- スキャンでハッシュ計算、画像読み込み、Office解析、動画プローブはしません。
- 一覧とフォルダツリーはDBから表示します。画面描画で元ファイルへアクセスしません。
- サムネイル取得用の子プロセスが元ファイルを `rb` で読み、アプリの作業領域へコピーします。生成に元のパスを渡しません。ユーザーによる閲覧操作では元ファイルを開きます。
- ファイルサイズ・更新日時が同一の変更は自動検出できません。必要時は手動再生成します。
- 別PCの変更はこのPCのBox Driveに反映された後に定期スキャンで検出します。クラウドへの直接問い合わせはありません。
- メタデータの同期通信までゼロにする仕様ではありません。
- シンボリックリンクとディレクトリジャンクションは再帰しません。Boxのreparse pointを一律に除外する処理はありません。

## 対応形式と生成

| 種類 | 拡張子 | 表示内容 |
|---|---|---|
| 画像 | jpg/jpeg/png/bmp/gif/webp | 最初の画像・フレーム |
| TIFF | tif/tiff | 一覧は先頭ページ、全ページを別窓で表示 |
| 動画 | mp4/mov/avi/mkv/wmv/m4v/webm/mpg/mpeg | 最初にデコードできるフレーム |
| PowerPoint | ppt/pptx/pptm | 一覧は先頭スライド、全スライドを別窓で表示 |

長辺最大512px、品質85のJPEGをDBに保存します。画像のEXIF回転を反映し、透明部分は白背景にします。PowerPointは読み取り専用・マクロ無効で開きます。パスワード保護や修復が必要なファイルなどは失敗する場合があります。動画は最初のフレームが黒いことがあります。

取得・生成は最大3件の別プロセスで行います。検出から3秒の待機と生成前後のサイズ・更新日時比較で、書き込み途中や古い結果の保存を抑制します。失敗時は既存サムネイルを保持し、エラーをツールチップで表示します。通常エラーは10分後に再試行しますが、タイムアウトは手動再試行まで保留します（元ファイルのサイズ・更新日時が変わった場合は解除）。取得開始から生成完了まで既定30分で打ち切ります。1～1440分で変更でき、大容量ファイルでは60分などに延長してから再試行してください。FFmpegを含め、外側の時間上限で統一しています。遅いファイルが1件あっても他の生成とメタデータスキャンは進みます。3枠とも待機中なら次の生成は空き待ちになります。終了時は自アプリが起動した生成プロセスの停止を要求します。Box自身の内部ダウンロードが停止する保証はありません。外部アプリで開く操作には、この時間上限は適用されません。

「タイムアウトのみ」で絞り込んでから「表示中のタイムアウトを再試行」でまとめて予約できます。個別の右クリック「再スキャン・再生成」または選択後「選択を再生成」も利用できます。「自動生成」がOFFの場合はONにすると生成を開始します。スキャン自体はメタデータ確認のためファイル本体を読みません。

サムネイル生成時は、動画も含めて全体をローカルへコピーしてから解析します。その分の取得時間とディスク空き容量が必要です。通常の作業コピーは処理後に削除します。旧0.2.0で作成済みの `previews` 内の閲覧用コピーは保持します。不要になったコピーは外部アプリを閉じてから手動で整理できます。

PowerPointのCOMサーバーは通常終了時に閉じます。ただしCOM停止・強制タイムアウト時にPowerPointプロセスが残る場合があります。他の作業中のPowerPointを巻き込む一括終了は行いません。

## 保存と常駐

DBはQtの `AppLocalDataLocation` が指すユーザーごとのローカル領域（Windowsでは通常 `%LOCALAPPDATA%` 配下のMediaCatalog関連フォルダ）に `catalog.sqlite3` として保存します。元データのフォルダやBoxの中には保存しません。設定も同じDBに保存します。

バックアップは上部の「DBバックアップ」を使用してください。稼働中にエクスプローラーでDB単体をコピーする方法は、WAL内の変更を取りこぼすため避けてください。

Windowsサインイン時に起動する場合は、`Win+R` → `shell:startup` にショートカットを置きます。

- リンク先: `"展開先\.venv\Scripts\pythonw.exe" "展開先\app.py" --tray`
- 作業フォルダー: 展開先

自動起動登録はユーザーが選択する方式です。本アプリはWindowsサービスではなく、サインイン中のトレイアプリです。スリープ中は実行されません。復帰時はタイマー経過後にスキャンします。「今すぐスキャン」は取得・生成と独立して開始します。前のスキャンが実行中の場合のみ、その完了後に再実行します。OS側でメタデータ列挙そのものが停止した場合、Pythonスレッドは強制終了できないためスキャンや終了が待機する場合があります。本体ダウンロード待ちは別プロセスで時間制限されます。

## 構成

- `catalog.py`: SQLite、メタデータ走査、更新判定、削除候補・承認処理
- `thumbnail_worker.py`: 画像 / FFmpeg / PowerPointの分離生成プロセス
- `app.py`: PySide6画面、非同期DBサムネイル読み込み、周期監視・トレイ常駐
- `tests/test_catalog.py`: 内容非読み取り、更新、削除、アクセス障害などの検証

一覧画像はバックグラウンドでDBから読み込み、画面に必要な画像を優先して最大600件のメモリキャッシュを保持します。項目情報は現在の絞り込み結果をまとめて読み込みます。数十万件規模のDB検索結果の分割取得、監視イベントによる即時反映、exe配布はこの版には含みません。
